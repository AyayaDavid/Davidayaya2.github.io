Manufacturing Quality Control Dashboard

Statistical process control (SPC) analysis of a real semiconductor production line: 1,567 production runs, 590 sensors, and pass/fail test results (UCI SECOM dataset, Jul to Oct 2008). By David Ayaya.

SPCp-chartI-MR control chartRoot-cause signalsPython & PandasChart.js

1. Is the failure rate stable? Weekly p-chart

Share of failed runs each week against 3-sigma control limits. Limits widen in weeks with fewer runs.

2. SPC check on the strongest signal: I-chart for sensor S060

Every run in time order. Control limits are set from the stable period (Aug 25 onward). Red points are runs that failed testing.

3. Failure rate by S060 level

Runs split into four equal groups by their S060 reading.

4. Sensors most associated with failure

Standardized difference (Cohen's d) between failed and passed runs; sensors with at most 5% missing data.

5. Data quality check

Number of sensors by share of missing readings.

Before vs after the process change

Runs before and after Aug 25, 2008.

Recommendations

  1. Monitor S060 on a live I-MR chart using the stable-period limits, and alert on any point outside them. Runs outside the limits failed about 4 times as often.
  2. Document what changed around Aug 25 (maintenance, recipe, material lot) in the change-control record, so the improvement is understood and held.
  3. Simplify the sensor set on operator dashboards. Drop the 116 sensors that never change and the 28 that are mostly missing, so attention goes to signals that matter.
  4. Confirm root cause before acting. This is observational data with anonymized sensors, so it shows association, not proven cause. The next step in a plant would be an investigation with process engineering.
